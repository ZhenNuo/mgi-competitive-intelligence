# MGI 竞争情报报告交付流程 v2.0

**版本**: v2.0  
**日期**: 2026-03-12  
**目标**: 标准化报告交付流程，提升用户体验

## 📋 交付流程图

```
报告生成 → 质量检查 → HTML 格式化 → 飞书预览 → 用户确认 → GitHub 归档
   ↓          ↓          ↓          ↓          ↓          ↓
Markdown   评分卡     样式优化    消息推送    反馈收集    Commit+Push
```

---

## 🚀 交付步骤详解

### Step 1: 报告生成

**输入**: 调研数据 + 模板  
**输出**: Markdown 报告  
**工具**: 自动化脚本 / 人工撰写  
**时间**: 30-60 分钟

**检查清单**:
- [ ] 报告元数据完整（日期、期号、周期）
- [ ] 核心摘要清晰（30 秒速读）
- [ ] 置信度标注完整
- [ ] 行动建议明确（RACI+ 截止时间）

---

### Step 2: 质量检查

**输入**: Markdown 报告  
**输出**: 质量评分卡  
**工具**: 情报质量评估体系  
**时间**: 5 分钟

**评估维度**:
| 维度 | 权重 | 检查项 |
|------|------|--------|
| 覆盖率 | 25% | 竞品/渠道/细分领域覆盖 |
| 时效性 | 25% | T+1 更新率、平均延迟 |
| 可信度 | 30% | A/B 级数据占比、交叉验证 |
| 可操作性 | 20% | 行动建议数量、RACI 明确率 |

**通过标准**: 综合得分 ≥ 4.0/5.0

---

### Step 3: HTML 格式化

**输入**: Markdown 报告  
**输出**: HTML 报告  
**工具**: 自定义 HTML 模板 / pandoc  
**时间**: 2-5 分钟

**样式要求**:
- 响应式设计（适配移动端/桌面端）
- 品牌色系统（MGI 蓝 #1a73e8）
- 卡片式布局
- 表格优化（斑马纹、悬停效果）
- 优先级标识（颜色区分）

**HTML 模板位置**: `templates/report_html_template.html`

---

### Step 4: 飞书预览

**输入**: HTML 报告  
**输出**: 飞书消息  
**工具**: 飞书机器人 / 手动发送  
**时间**: 1-2 分钟

**消息结构**:
```
📊 MGI 竞争情报 [报告类型] - [日期]

🔍 核心摘要
[30 秒速读内容]

📈 关键发现
1. [发现 1]
2. [发现 2]
3. [发现 3]

📋 行动建议
[立即行动项列表]

📄 完整报告：[HTML 文件预览/附件]

---
情报质量：⭐️⭐️⭐️⭐️ (4.25/5)
下次报告：[日期]
```

**发送时间**:
- 三日报：周一/周四 9:00 AM
- 周报：周日 9:00 AM

---

### Step 5: 用户确认

**输入**: 飞书消息  
**输出**: 用户反馈  
**方式**: 飞书回复 / 表情反应  
**时间**: 即时 - 24 小时

**反馈类型**:
| 反馈 | 响应 |
|------|------|
| 👍 确认 | 进入 Step 6 归档 |
| ❓ 疑问 | 补充说明 / 修正 |
| ✏️ 修改 | 修订后重新发送 |
| ➕ 追加 | 补充内容后归档 |

---

### Step 6: GitHub 归档

**输入**: 最终报告（Markdown+HTML）  
**输出**: Git Commit + Push  
**工具**: Git CLI  
**时间**: 1-2 分钟

**提交规范**:
```bash
feat: 生成 [报告类型] [日期]

- 调研周期：[开始日期] ~ [结束日期]
- 核心发现：[1-2 句话]
- 情报质量：[评分]/5.0
```

**示例**:
```bash
feat: 生成三日报 2026-03-12

- 调研周期：2026-03-09 ~ 2026-03-12
- 核心发现：MGI 收购整合推进，贝克曼 AI 平台实施，中国竞品缺口持续
- 情报质量：4.25/5.0
```

## 🔧 自动化脚本

### 交付脚本（伪代码）

```bash
#!/bin/bash
# 报告交付自动化脚本

REPORT_DATE=$1
REPORT_TYPE=$2  # tri_daily / weekly

# Step 1: 生成报告
generate_report $REPORT_TYPE $REPORT_DATE

# Step 2: 质量评估
SCORE=$(evaluate_quality $REPORT_DATE)
if (( $(echo "$SCORE < 4.0" | bc -l) )); then
    echo "⚠️ 质量得分低于 4.0，请人工复核"
    exit 1
fi

# Step 3: 生成 HTML
generate_html $REPORT_DATE

# Step 4: 发送飞书
send_feishu_message $REPORT_TYPE $REPORT_DATE $SCORE

# Step 5: 等待确认（超时 24h）
wait_for_confirmation 86400

# Step 6: Git 归档
git_add_commit_push $REPORT_DATE

echo "✅ 交付完成"
```

## 📝 异常处理

### 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 飞书发送失败 | 网络问题/机器人配置 | 检查网络，重试 / 检查机器人配置 |
| HTML 生成失败 | pandoc 未安装 | 安装 pandoc 或手动转换 |
| Git 推送失败 | 网络问题/权限 | 检查网络，验证 SSH key |
| 用户未确认 | 忙碌/消息遗漏 | 24h 后提醒 / 电话确认 |

### 降级方案

- **HTML 不可用**: 发送 Markdown 纯文本
- **飞书不可用**: 发送邮件 / WhatsApp
- **自动化失败**: 人工执行各步骤
